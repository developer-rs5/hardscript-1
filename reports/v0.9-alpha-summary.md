# v0.9-alpha — the registry ecosystem

Summary generated on 2026-09-28 from the QA run, the benchmark data in
`reports/raw/`, and the git history. Regenerate with `qa/summary.py`.

## What v0.9-alpha is

A package ecosystem: a registry service, a client that can publish,
download, resolve, search, authenticate, verify signatures, and survive
the registry going away. Ten commits, one branch, no deployment code
touched.

```
hard publish                 build a .hspkg and sign it
hard add jwt                 resolve, download, verify, link, lock
hard search --tag auth       ranked search across every mirror
hard verify jwt@1.10.0       check a signature against the trust store
hard registry health         is the registry reachable, and with which key
hard install --offline       from the cache, with no network at all
```

## Bugs the milestones found

Each of these was found by a test or a benchmark, not by reading code:

| where | what was wrong |
| --- | --- |
| `SqliteStore::latest` | ordered versions as *text*, so a package with 1.9.0 and 1.10.0 reported 1.9.0 as latest |
| `Version: Ord` | ranked a pre-release above its own release (1.10.0-rc.1 > 1.10.0) |
| registry `/search` | `?tag=` silently degraded into "match everything"; `total` equalled the page size |
| `pm/src/toml.rs` | `[[array.of.tables]]` was parsed as a plain table, so mirror syntax could not be read at all |
| `pm/src/registry.rs` | a failed `curl` returned `Ok(status 0)`, so every https failure looked like a reply and could not trigger mirror fallback |
| `pm/src/registry.rs` | a refused connection was retried with a 200ms+400ms backoff: 600ms of sleeping before every fallback |
| resolver | yanked versions were never filtered, so `hard yank` had no effect on a fresh install |
| `hard install` | ignored the manifest's `[registry] default` while `hard search` used it |
| `hard download` | `--force` did not force anything and `--output` wrote nothing |
| `Cache::repair` | removed the archive but left the extracted sources, so stale code could be linked |
| install verification | under `warn`, a failed check produced no warning at all |

## Known limits

- **The signing key is a test key by default.** A real registry must
  supply `HARD_REGISTRY_SIGNING_KEY`; `/keys` and `hard doctor` both say
  so out loud.
- **No TLS in the registry itself.** Put it behind a reverse proxy.
- **PBKDF2 at 100 000 iterations**, not Argon2id. The work factor is one
  constant in `hard-registry/src/security.rs`.
- **Names are global per registry.** No namespaces.
- **One lockfile resolves against one set of registries.**
- **`hard install` has no install scripts.** A package is data.
- **Sanitizer runs cover the unit and integration tests, not the shell
  suites**: the shell suites spawn a release binary, which is not built
  with a sanitizer.
