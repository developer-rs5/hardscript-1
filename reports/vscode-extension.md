contributed surface, debug adapter, and measured smoke results.

## Debug Adapter Smoke Results

`qa/extension/dap_smoke.py` runs the packaged DAP adapter over stdio against
`examples/hello-world/main.hard` with a breakpoint on line 8, using
`target/release/hard` as the debuggee. All 8 cases pass and the adapter exits with
code 0.

| Case | Duration | Detail |
| --- | --- | --- |
| `initialize` | 60.374 ms | capabilities negotiated |
| `launch` | 1.212 ms | launched `main.hard` |
| `set_breakpoints` | 0.892 ms | line 8 verified |
| `configuration_done` | 0.391 ms | configuration accepted |
| `program_start` | 5.584 ms | stopped at line 8 |
| `program_output` | 6,613.785 ms | output categories `console` and `stderr` |
| `stack_and_scopes` | 0.479 ms | 1 scope |

Event sequence observed: `initialized`, `output`, `output`, `process`, `thread`,
`stopped`, `output`, `exited`, `terminated`.

The `program_output` duration is dominated by `hard build` compiling the debuggee
in the temporary directory, not by the adapter. Raw results are written to
`qa/extension/results.json`, which is git-ignored and regenerated by the command
above.

Reproduce with:

```
./qa/run-extension-tests.sh
```

## Protocol QA Against the Real Server

The extension is exercised against the same server binary the editor would start.
`./qa/run-lsp-tests.sh` passes 15/15 cases over stdio JSON-RPC with an empty server
stderr, covering hover, definition, references, completion, document symbols,
semantic tokens, signature help, prepare rename, rename, formatting, code actions,
`workspace/executeCommand`, workspace symbols, background workspace indexing, and
`textDocument/didChange`. The `code_action` case resolves an Explain Error code
action, which is the same path the `hardscript.explainError` command uses.

`initialize` returns in 4.679 ms against the debug binary; request latencies in
that suite range from 0.24 ms to 1.78 ms.

## Packaging Hygiene

- `dist/` is not committed; the VSIX is a release artifact built by the commands
  above.
- `vscode-hardscript/node_modules` is installed by `npm ci` and is not committed.
- `vscode-hardscript/.vscode/launch.json` and `vscode-hardscript/.vscode/tasks.json`
  are tracked through narrow `.gitignore` exceptions so extension debugging
  configurations stay in the repository.
- The packaged `package.json` advertises no `repository` field requirement, no
  bundled server binary, and no activation on startup, so the extension only starts
  the server when a HardScript document, command, task, or debug session is used.
